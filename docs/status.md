## 影响正式评价的问题

### 1. 实验时间口径与原始标签（2026-11-08更新）

用户确认：沿用实际运行时的信息范围，在下一交易日开盘交易。原实验日线行情截至信号日D收盘，财报工具按D纽约时间23:59:59及公开时间筛选，Finnhub新闻窗口仍为D−7至D−1。

实际报告包含GOOGL / 2026-07-22当晚21:15:54公开的财报、AMZN / 2026-07-30当晚22:11:13公开的财报。这些时刻均在下一交易日开盘之前，按确认后的执行口径属于允许使用的信息；不再仅因其晚于D收盘，就将这两例判为未来信息泄漏或要求重跑。

原始CSV/日志却填写D收盘information_cutoff与收盘+30分钟decision_time，因此这两个字段是旧版时间标签，不能准确证明实际输入截止。原运行日志中按收盘计算的财报快照哈希也不能充当实际工具完整输入的哈希。本次保留原始标签、动作、报告及日志，只修订声明，不伪造原始审计记录。

该口径没有声称读取次日盘前、周末或假日期间的全部新信息。整理后的当前vendor仍采用收盘过滤；后续复现旧实验前应同步代码和时间字段。此前“盘后财报泄漏”的判断基于旧声明，现按用户确认的新解释更正。

### 2. 2024 复现存在并发重复运行

重复 cell 恰好为 manifest 顺序 32—62。原始 runs.jsonl 中，这 31 组都有两次成功调用，且每组运行时间区间都重叠；当前写入函数只追加决策。

例如 AAPL / 2024-01-24 的两次调用开始于 2026-11-03 15:56:08 UTC 和 15:56:40 UTC，结束于 16:02:21 和 16:02:07，分别输出 SELL / HOLD。日志支持并发重复执行这一判断，但未取得当时终端命令，不能确定具体启动方式。不能未经依据就选择冲突结果中的某一条作为正式结果。
